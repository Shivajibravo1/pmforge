## "Which kind of AI do we need?"

Three Lighthouse directors have asked for AI. The sales director wants better forecasts. The service director wants an assistant that answers customer questions. The operations director wants something that books engineers and orders parts on its own. They all say "AI". They do not mean the same thing.

```chat
# Workshop, Tuesday, 11:00 AM
Sales director | Sales | We need to predict which customers will leave next quarter.
Service director | Customer service | We need something that answers questions from our policy documents.
Operations director | Operations | We need something that does the booking and ordering by itself.
Rahul Mehta | Lead developer | Those are three different technologies with three different risks.
```

The right solution depends on the problem. Choosing the wrong type wastes money and creates risk. A project manager should know the main families, what each is good at, where each fails and what each needs from the business.

```key
Match the technology to the task. Prediction needs historical data and measurement, text answers need good source documents and checks, actions need permission limits and human oversight.
```

## Four families

```cards
chart | Machine learning | Learns patterns from labelled data to predict or classify, such as churn, fraud or demand. | Biased or stale training data.
pencil | Generative AI | Produces text, images or code from prompts. | Fluent answers that are wrong.
search | Retrieval augmented generation | Finds relevant documents first, then asks a model to answer from them with sources. | Poor documents, wrong retrieval and access leaks.
robot | Agents | Systems that plan and call tools to complete tasks, with some autonomy. | Wrong actions, with real consequences.
```

## Fit to the problem

| Need | Often suited to | Main caution |
| --- | --- | --- |
| Predict a number or category from history | Machine learning | Needs good labelled data and ongoing monitoring |
| Draft or summarise text | Generative AI | Check facts, tone and confidentiality |
| Answer from company documents | RAG | Keep sources current and enforce access rights |
| Carry out multi step tasks | Agents | Limit tools, require approval for risky actions |
| Fixed rules and clear logic | Ordinary software | AI may be unnecessary |

## A decision path

```flow
Is the logic known and stable | If yes, use normal software
Is there historical data with outcomes | If yes, consider machine learning
Is the task language based | Consider generative AI
Must answers come from your own documents | Consider RAG with citations
Must it act in systems | Consider an agent, with limits and approval
```

## How a RAG assistant works

```arch
User question | Typed into the assistant
Retrieval | Search the knowledge base for relevant passages the user may access
Prompt assembly | Build a prompt from instructions, passages and the question
Model | Generate an answer based on the supplied passages
Checks | Validate format, sources and policy
Answer | Show with citations and a route to a human
```

## Your decision

The operations director wants an autonomous agent that books and orders parts without approval, to save time.

```decision
? What do you recommend?
- Build the fully autonomous agent for speed | One wrong order or booking has real cost, and you have no controls.
- Refuse all agent use | You lose a chance to save effort where the risk is low.
+ Start with an agent that proposes bookings and orders, a human approves each one, track how often the proposals are right, and allow automatic actions only for low value, reversible tasks after evidence supports it | You gain speed with controlled risk, and trust is earned by data.
= Give agents limited, reversible authority first and widen it with evidence.
```

## Cost and effort differences

```accordion
Machine learning | Data work and labelling take the most effort. Models can be small and cheap to run.
Generative AI | Quick to prototype. Costs scale with usage, and quality control needs ongoing effort.
RAG | Most of the work is in the documents, search quality and access control.
Agents | Highest design and testing effort, because actions need guardrails and audit trails.
```

## Risk profile

```rag
Machine learning | A | Data bias and drift
Generative AI | A | Wrong or leaked content
RAG | A | Poor sources, permission gaps
Agents | R | Actions with consequences
Conventional software | G | Predictable behaviour
```

**Names change fast**

Terms such as agent, copilot and assistant are used loosely by vendors. Ask what the system does, what data it uses, what it is allowed to do and how it is measured. Check current definitions in standards such as ISO/IEC 22989 for AI terminology.

## AI and PM judgement

```cards
brain | Do not start with the tool | Start with the problem and the measure of success. | Buying AI first and finding a problem later.
users | Ask who is accountable | Every system needs a named owner. | Shared ownership that means none.
file | Ask for evidence | Request evaluation results, not demos. | Decisions based on a clever demo.
```

```ai
For every AI proposal, ask five questions: what problem, what data, what measure, what could go wrong and who is accountable. If a vendor cannot answer, do not proceed.
```
