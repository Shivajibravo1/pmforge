## "Why is the bill so high?"

The Lighthouse pilot assistant has been popular. Usage is up fivefold. So is the invoice from the model provider. Finance wants to know what drives it, and whether the cost will keep climbing as the service reaches all customers.

```chat
# Message, Thursday, 11:00 AM
Finance partner | Finance | The usage charge is five times last month. Is this a one off?
Rahul Mehta | Lead developer | Longer conversations, more documents in each prompt and a larger model on the hard cases.
Victoria Hale | COO | Then what will it cost at full volume? And is it fast enough for customers?
```

Generative AI is usually priced by usage, and the unit is the token. A token is a small piece of text, often a word or part of a word. You pay for tokens sent to the model, called input, and tokens it writes back, called output. Cost and speed depend on the model you choose, the length of the prompt, the amount of retrieved text and the length of the answer. A PM who can estimate these in a spreadsheet is far more useful than one who says "it depends".

```key
Cost per answer equals input tokens times input price plus output tokens times output price, summed over calls. Multiply by volume, and test the assumptions with real measurements.
```

## What drives the cost

```cards
file | Prompt length | Instructions, history and examples are sent every time. | Long prompts repeated on every call.
database | Retrieved text | Each passage you add to the prompt costs input tokens. | Sending ten passages when two would do.
pencil | Answer length | Output tokens are usually priced higher than input tokens. | Verbose answers nobody reads.
brain | Model choice | Larger models cost more and are slower. | Using the biggest model for easy questions.
repeat | Calls per task | Agents and chains make several calls per request. | Hidden loops that multiply cost.
```

Prices and model names change often. Always take current prices from the provider's pricing page and record the date.

## Speed

```accordion
Latency | Time until the answer appears. Larger models, longer prompts and more calls increase it.
Streaming | Showing words as they appear improves perceived speed.
Caching | Reusing repeated prompt parts can cut cost and time where supported.
Rate limits | Providers limit how many requests or tokens you can use per minute. Plan for peak load.
```

## Ways to reduce cost without hurting quality

```flow
Measure | Tokens and cost per call, by feature
Trim | Shorten prompts, send fewer, better passages
Route | Send easy questions to a smaller model and hard ones to a larger model
Cache | Reuse repeated content, and answers to common questions where appropriate
Limit | Cap answer length and set budgets and alerts
Review | Compare cost per resolved query with quality
```

```ref
Azure | Well-Architected Framework, cost optimization pillar | Caching, smaller models and prompt design reduce cost. Check quality after each change.
```


## A simple model

| Item | How to calculate |
| --- | --- |
| Input tokens per call | Prompt plus retrieved text plus history, measured |
| Output tokens per call | Average answer length, measured |
| Cost per call | Input tokens times input price plus output tokens times output price |
| Calls per resolved query | Measured average, including retries and tool calls |
| Monthly cost | Cost per call times calls per query times queries per month |
| Cost per resolved query | Monthly cost divided by queries resolved without a human |

Use measured values and the current price list. Do not use numbers from examples.

## Your decision

At full volume, the projected cost is above the benefit in the conservative case. The team suggests switching to a smaller model for everything.

```decision
? What do you recommend?
- Switch everything to the smaller model | Quality may drop on hard questions, and complaints cost more than tokens.
- Accept the higher cost, and hope volume pays for it | You overspend with no plan.
+ Run the evaluation set on the smaller model, route the questions that pass to it and keep the larger model for the hard cases, trim the prompt and retrieved text, cap output length and set a budget alert, then recalculate cost per resolved query | You cut cost where it is safe and protect quality where it matters.
= Route by difficulty, trim waste and measure quality alongside cost.
```
