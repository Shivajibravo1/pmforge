## "What could go wrong?"

Before building the Lighthouse assistant, Elena asks a deceptively simple question at the design review: what could go wrong, and who would want it to? The room goes quiet. Nobody has written it down.

```chat
# Design review, Tuesday, 2:00 PM
Elena Rossi | CISO | Before we write more code, I want a threat model. What are we protecting, from whom, and how would they get in?
Rahul Mehta | Lead developer | We have security scans in the pipeline.
Elena Rossi | CISO | Scans find mistakes in code. They do not find mistakes in design.
```

A threat model is a structured way to look at a design and find what could go wrong before it is built. STRIDE is a widely used memory aid, developed at Microsoft, for six categories of threat. The result is a list of threats, the controls that address them and the security requirements that flow into the backlog.

```key
Threat modelling finds design level problems when they are cheap to fix. It turns "be secure" into specific, testable requirements.
```

## STRIDE

```cards
user | Spoofing | Pretending to be someone or something else. | Weak authentication and stolen tokens.
edit | Tampering | Changing data or code without permission. | Unsigned updates and unprotected data.
file | Repudiation | Denying an action when there is no proof. | Missing or editable logs.
eye | Information disclosure | Exposing data to people who should not see it. | Overly broad access and verbose errors.
zap | Denial of service | Making a system unavailable. | No limits on requests or costs.
key | Elevation of privilege | Gaining rights beyond those granted. | Missing authorisation checks.
```

```ref
MITRE | ATT&CK and ATLAS knowledge bases | ATT&CK describes attacker behaviour. ATLAS covers AI specific threats.
OWASP | Threat Modeling Cheat Sheet | Practical steps for a team to run a threat model.
```


## Four questions

```flow
What are we working on | Draw the system, data flows and trust boundaries
What can go wrong | Apply STRIDE to each element and flow
What will we do about it | Mitigate, accept, transfer or avoid
Did we do a good enough job | Review, test and revisit as the design changes
```

```ref
Azure | STRIDE threat categories: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege | STRIDE originated at Microsoft. Know the six categories and give one example of each.
```


## A data flow for the assistant

```arch
Customer | Browser or app, outside the trust boundary
API gateway | Authentication, rate limits, logging
Assistant service | Builds prompts, calls the model, calls tools
Model service | Hosted language model
Order system | Customer and order data, behind a tool
```

## Example threats and requirements

| Element | STRIDE | Threat | Requirement |
| --- | --- | --- | --- |
| Customer to gateway | Spoofing | Stolen session token | Short lived tokens, multi factor for sensitive actions |
| Assistant to order system | Elevation | Assistant reads another customer's order | Tool uses the customer's identity, with authorisation checks |
| Logs | Repudiation | No record of what the assistant did | Immutable logs of tool calls with user and time |
| Prompt | Tampering | Instructions hidden in a customer message | Treat user text as data, validate outputs, limit tool power |
| Public endpoint | Denial of service | Flood of requests drives cost | Rate limits and budget alerts |

## Your decision

The team has three weeks left. They ask whether they can skip the threat model and rely on the scans.

```decision
? What do you recommend?
- Skip it, because scans are enough | Design flaws, such as an assistant that can read any order, are invisible to scans.
- Run a full week long model with every team | The time is not available, and the launch is hurt.
+ Run a focused half day session on the highest risk flows, with the architect, a developer, the CISO and a tester, record threats and turn the top ones into backlog items with owners and tests | You get most of the value in a few hours, and the findings enter delivery.
= Time box it and focus on the highest risk data flows. Output must be backlog items.
```

## Turning threats into delivery

```timeline
Workshop | Draw flows, apply STRIDE, rank threats | info
Day 2 | Add security requirements and acceptance criteria to the backlog | ok
Sprint | Build controls, write tests | ok
Release | Verify controls with testing and review | ok
Change | Revisit the model when the design changes | info
```

## Risk ranking

```rag
Cross customer data access | R | Top priority, design fix needed
Prompt injection | R | Needs layered controls and testing
Missing audit trail | A | Logging requirement added
Cost abuse | A | Rate limits planned
Token theft | A | Standard controls in place
```

## AI specific threats

```cards
brain | Prompt injection | Instructions hidden in user or document text. | Assistant follows an attacker.
database | Data leakage | The model reveals data from its context or training. | Sensitive information in answers.
robot | Excessive agency | Tools that can do more than needed. | Actions the user never authorised.
coins | Model denial of wallet | Abuse that drives up cost. | Surprise bills and outages.
```
