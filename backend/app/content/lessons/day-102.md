## "Give me the model in a sheet"

Finance has asked for a cost model for the support assistant that they can open, change and trust. It should show cost per resolved query, monthly cost at three volumes and the effect of cost saving choices. They want to change an assumption and see the result.

```chat
# Message, Friday, 9:00 AM
Finance partner | Finance | A sheet, not a slide. I want to type in volume and see the monthly cost and the cost per resolved query.
Rahul Mehta | Lead developer | I can give you measured token counts from the pilot.
Victoria Hale | COO | And add the human cost. If staff review ten percent of answers, show it.
```

A cost model is a small spreadsheet that makes assumptions visible and lets people test them. A good one separates inputs from calculations, labels each assumption with its source and date, shows ranges and includes costs people forget, such as review time, monitoring and improvement.

```key
A good cost model is transparent. Anyone can see each assumption, change it and watch the effect. It is a tool for conversation, not a number to defend.
```

## Structure

```flow
Inputs | Volume, tokens, prices, resolution rate, review rate, staff cost
Calculations | Cost per call, per query, per month
Scenarios | Low, expected and high volume
Sensitivity | Which inputs move the answer most
Outputs | Monthly cost, cost per resolved query, payback
```

## Sensitivity

```timeline
Base case | Expected volume, measured tokens and resolution rate | info
Volume double | Check platform limits and discounts | warn
Resolution rate lower | Human cost rises, benefit falls | bad
Prices change | Re check with current price list | warn
Prompt trimmed | Input tokens fall, quality tested first | ok
```

```ref
PMI | PMBOK Guide, quantitative risk analysis and sensitivity analysis | Show best, expected and worst cases. Say which input moves cost the most.
```


## Your decision

Finance wants a single cost figure for next year's budget. Usage is uncertain, and prices may change.

```decision
? What do you give them?
- A single number, rounded and padded | The padding is hidden, and nobody knows what could move it.
- Only a formula, no figure | Finance cannot budget without a number.
+ A base figure with a low and high range, the three assumptions that matter most, a monthly review point and a rule for what happens if usage exceeds the high case, such as a cap or a funding request | Finance gets a budget line and a way to manage the uncertainty.
= Give a budget number with range, key drivers and a response rule for overruns.
```

## Layout of the sheet

| Sheet | Contents |
| --- | --- |
| Inputs | Every assumption in one place, with source and date |
| Calculations | Formulas only, no typed numbers |
| Scenarios | Low, expected and high volume |
| Sensitivity | Effect of changing each key input |
| Summary | Monthly cost, cost per resolved query, and comparison with the benefit |
| Notes | Method, version and who reviewed it |

```incident
# Cost model that only counted tokens (illustrative)
What happened | A cost model for an AI assistant counted tokens only. Retrieval storage, monitoring, evaluation runs and human review were missing.
Impact | Actual run cost was well above the model and the case was reopened.
Root cause | The model was built from the vendor price page and did not list costs outside tokens.
Resolution | The PM added all cost categories, stated assumptions, ranges and a sensitivity view, and had finance review it.
PM move | List all cost categories, not only token price, and show sensitivity.
```
