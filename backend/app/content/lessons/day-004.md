## You do not need to code. You do need to understand.

Technical literacy lets you ask better questions, spot unrealistic estimates and earn the team's trust. The goal is fluency, not engineering depth.

## Four ideas to own

```cards
workflow | SDLC | Software development life cycle: plan, design, build, test, release, operate. Know where your project is and what must be true to move on.
layers | Environments | Separate copies of the system: development, test, staging, production. Problems found in production cost far more than those found in test.
link | APIs | A defined way for one system to ask another for data or actions. Ask who owns it, its availability commitment, and what happens if it changes.
cloud | Cloud basics | You rent computing and services. The provider secures the platform; you stay responsible for your data, access and configuration.
```

```flow
Developer laptop | Code is written
Test | Checks run
Staging | Production-like rehearsal
Production | Real users, real data
```

```key
Shared responsibility: the cloud provider secures the underlying platform. You remain responsible for your data, access and configuration.
```

## Questions that make you credible

```accordion
Which environment is this demo running in? | Tells you how much the result proves. A demo in development says little about production behaviour.
What is the rollback plan if the release fails? | A release without a tested way back is a gamble with other teams' systems.
Which other systems call this API? | Reveals hidden dependencies that a change can break.
Who has production access and how is it approved? | A basic security and audit question that CISOs will ask anyway.
What is not tested yet? | Forces an honest list of gaps instead of a green dashboard.
```

```quiz
? Who is responsible for configuring access to your data in a cloud service?
- The cloud provider alone
+ You, under the shared responsibility model
- Nobody, it is automatic
= The provider secures the platform. Your data, access and configuration remain yours.
```

## Check yourself

```tip
Write the path your project's change must take from a developer's laptop to production in your organisation. Mark each approval or gate on the path. Gaps in your answer are gaps in your plan.
```
