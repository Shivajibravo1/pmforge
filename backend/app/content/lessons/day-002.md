## Why the type matters

The type of IT project decides your risks, your team, your lifecycle and how you measure success. Treating a data migration like a website build is a common and expensive mistake.

## The five types you will meet

| Type | Typical examples | Main risk | Success looks like |
| --- | --- | --- | --- |
| Application | New portal, mobile app, ERP module | Scope growth, user adoption | Users complete real tasks, defects within threshold |
| Infrastructure | Network upgrade, data centre move, endpoint rollout | Downtime, hidden dependencies | No unplanned outage, documented rollback |
| Data | Migration, warehouse, reporting | Data quality, reconciliation | Reconciled counts, signed-off data owners |
| Security | Identity rollout, zero trust, vulnerability remediation | Business disruption, incomplete coverage | Measured risk reduction, audit evidence |
| AI | Chatbot, forecasting, document automation | Unclear value, data readiness, model behaviour | Measured accuracy and business impact, governance in place |

## Mixed projects are normal

A "new customer portal" is an application project, but it needs identity (security), integration with a customer database (data) and capacity planning (infrastructure). Name the primary type, then list the secondary types as workstreams with their own owners.

## A quick classification test

Ask three questions: What is the main thing being delivered? What would be hardest to reverse if it goes wrong? Who must sign off before go-live? The answers usually point to the dominant type.

## Check yourself
