## "Security will review it at the end"

Lighthouse's security review used to happen two weeks before launch. In the last release, it found a hardcoded password, a vulnerable library and an exposed test endpoint. Each fix needed rework. The launch slipped three weeks.

```chat
# Retrospective, Thursday, 3:00 PM
Elena Rossi | CISO | We found everything at the end. Fixing it was expensive and rushed.
Rahul Mehta | Lead developer | We did not know the rules until the review.
Daniel Okafor | Sponsor | Can we find these things earlier, when they are cheap to fix?
```

Shift left means moving security checks earlier in the delivery process, to where fixes are cheaper and faster. DevSecOps builds security into the pipeline and the culture, instead of treating it as a gate at the end. The aim is that security becomes part of everyday engineering work.

```key
The earlier a defect is found, the cheaper it is to fix. Automate the common checks in the pipeline and give developers fast, clear feedback.
```

## The four families of checks

```cards
code | SAST, static analysis | Scans source code for insecure patterns without running it. | False positives that train people to ignore results.
globe | DAST, dynamic analysis | Tests a running application from outside, like an attacker. | Late in the process and limited coverage.
package | SCA, composition analysis | Checks third party libraries for known vulnerabilities and licences. | Findings in libraries nobody uses.
key | Secrets scanning | Finds passwords, keys and tokens in code and history. | A key committed once stays in history.
```

Other checks include container image scanning, infrastructure as code scanning and software bills of materials. Tool names and features change. Check current documentation.

```ref
OWASP | DevSecOps Guideline | Know the four families: SAST, DAST, software composition analysis and secrets scanning, and where each runs in the pipeline.
NIST | SP 800-218 SSDF | Pair each check with the secure development practice it supports.
```


## Where checks fit

```flow
Design | Threat modelling and security requirements
Code | Peer review, IDE hints, secrets scanning before commit
Build | SAST, SCA, image scan, signed artifacts
Test | DAST, API tests, abuse case tests
Release | Policy checks, approvals, provenance
Run | Monitoring, patching, vulnerability management
```

## Make findings usable

```accordion
Severity and context | Rank by exploitability and exposure, not only by a score.
Fast feedback | Show findings in the pull request, not in a separate report weeks later.
Ownership | Each finding has an owner and a due date based on severity.
Exceptions | A documented, time limited exception route with approval.
Noise control | Tune rules, and measure false positives.
```

```ref
CIS | Controls v8, application software security | Tie findings to a standard so priorities are defensible.
OWASP | Top 10 | Use it as a shared language for the most common web application risks.
```


## Your decision

The new scan reports four hundred findings. The team is overwhelmed, and the launch is in six weeks.

```decision
? What do you do?
- Block the release until all four hundred are fixed | The team stops delivering and the number is not the right measure.
- Turn off the scan to reduce noise | You lose the benefit and the exposure remains.
+ Triage by severity and exposure with Elena, block only new critical and high findings from now on, schedule fixes for existing ones by risk, and track the trend weekly | You stop adding new risk, and reduce the old risk in order of importance.
= Stop the bleeding first by blocking new serious issues, then work down the existing backlog by risk.
```

## Culture

```cards
users | Security champions | A developer in each team who knows the basics. | A champion with no time allocated.
book | Short training | Ten minute lessons linked to real findings. | Annual compliance courses that nobody remembers.
heart | Blameless handling | Reward reporting, not hiding. | Fear that makes people skip reporting.
```

## AI and shift left

```cards
code | AI generated code | Can include insecure patterns or outdated libraries. | Code accepted without review.
search | AI assisted triage | Summarises findings. | Wrong prioritisation with confident wording.
shield | Prompts and tools | Prompts, tool permissions and data flows need review as code does. | Prompt injection weaknesses nobody tested.
```

```ai
Treat AI generated code like code from a new contractor: review it, scan it and test it. Add checks for prompt injection, tool permissions and data leakage in the pipeline for AI features. Frameworks such as the OWASP Top 10 for LLM applications can guide the test list; check the current version.
```

```ref
OWASP | Top 10 for LLM Applications | AI generated code and prompts need review for the same classes of issues plus LLM specific ones.
```
