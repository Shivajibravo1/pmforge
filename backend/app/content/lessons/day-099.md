## "It seemed fine in the demo"

The vendor's demo of the Nimbus support assistant was impressive. It answered five questions beautifully. In the first week of the pilot, it answered a returns question with a rule that does not exist. When Daniel asks how good the system really is, nobody has a number.

```chat
# Message, Tuesday, 10:20 AM
Daniel Okafor | Sponsor | The demo was great. How often is it right?
Rahul Mehta | Lead developer | I do not know. We tried it on a few questions.
Victoria Hale | COO | Then we do not know if it is ready.
```

A project manager does not need to write prompts all day. You do need to understand what a good prompt is, why small changes alter results and how to measure quality with an evaluation set, often called an eval. Without evaluation, an AI project runs on impressions, and impressions are not evidence.

```key
You cannot manage what you cannot measure. An evaluation set turns "it seems good" into a rate that you can track, compare and set thresholds against.
```

## Parts of a good prompt

```cards
user | Role and task | What the assistant is, and what it must do. | Vague roles and goals.
book | Context and sources | The documents and facts to use. | Asking the model to rely on memory.
list | Rules and limits | What it must not do, and when to hand over. | Unstated boundaries.
pencil | Format | Structure of the answer, citations, length. | Output that cannot be checked.
star | Examples | A few good examples of input and answer. | Examples that bias or leak.
```

Treat user text and retrieved documents as untrusted data. Instructions must be kept separate from content, as you will see in the security lessons.

```ref

```


## Evaluation sets

An evaluation set is a collection of realistic questions with the expected answer or the criteria for a good answer. You run it every time something changes, and compare scores.

```flow
Collect | Real questions from tickets and staff, including hard and sensitive ones
Label | Expected answer, source document and acceptable alternatives
Score | Correct, partly correct, wrong, unsafe, or refused appropriately
Run | Against each version of the prompt, data and model
Compare | Track results and investigate regressions
Grow | Add every real failure to the set
```

```ref
NIST | AI RMF Measure function | Use a fixed evaluation set with expected answers and a scoring method. Track results by version.
NIST | AI 600-1 Generative AI Profile | Reference for generative AI risks to test, such as confabulation and harmful content.
```


## What to include

```accordion
Easy questions | Basic checks that must always pass.
Hard questions | Ambiguous, multi step or poorly phrased questions.
High stakes | Refunds, safety, legal and sensitive topics, with handover expected.
Out of scope | Things the assistant must decline.
Attack cases | Attempts to override instructions or extract data.
Edge cases | Odd formatting, other languages, long messages.
```

## Ways to score

```cards
user | Human review | The most reliable for quality and tone, but slow. | Reviewers who disagree with no guide.
robot | Automated checks | Rules, string matches and, with care, a model used as a judge. | A judge that shares the same blind spots.
chart | Business measures | Resolution rate, escalations, complaints. | Slow signal, many causes.
```

## Your decision

The team has twenty test questions, all written by developers who know the system well. They propose to launch if all twenty pass.

```decision
? What do you recommend?
- Launch, since all twenty passed | The set is small, easy and written by the builders.
- Demand a thousand questions before any pilot | Too slow for an early pilot.
+ Ask service staff to contribute real, difficult and sensitive questions, expand to a representative set that covers each topic, agree thresholds by category, such as zero tolerance for unsafe answers, and treat twenty passes as a smoke test, not a release gate | The evidence matches the risk, and the set grows with experience.
= A small passing set proves little. Make it representative, and set thresholds by risk.
```

## Evals and AI

```cards
file | AI drafts questions | A fast start. | Questions that look artificial.
search | Model as judge | Scales scoring. | Biased scores and self agreement.
users | Humans stay in the loop | Review a sample of judged results. | Trusting the automated score alone.
```

```ai
Shift | Evaluations are the acceptance tests of AI, and a PM should be able to read them.
Example (illustrative) | A team asks AI to write evaluation questions. The PM replaces half with real customer wording and has experts check the answers.
Use AI to | Draft and expand evaluation questions, suggest edge cases and group them by topic.
Keep human | Sourcing the core set from real user language and having experts verify expected answers.
Risk | An evaluation set that resembles the model's own idea of a good question.
Control | Review a sample of any automated scoring by hand and keep the set fixed so results can be compared.
Interview line | I source the core evaluation set from real user language, have experts verify the answers and review a sample of automated scoring by hand.
```



```incident
# "It seemed fine in the demo" (illustrative)
What happened | A prompt looked good in a demo with five questions. After launch, answers on less common questions were wrong.
Impact | Support handled complaints and the sponsor lost confidence.
Root cause | There was no eval set covering typical, edge and risky questions, and no pass threshold.
Resolution | The team built an eval set from real questions with expected answers, a scoring sheet, thresholds and a rerun on every prompt change.
PM move | Require an eval set and threshold before launch and on each change.
```

## What to remember

```checklist
Prompts have role, context, rules, format and examples
Use an evaluation set to measure, not impressions
Include hard, high stakes, out of scope and attack cases
Set thresholds by category
Add every real failure to the set
```


```mindmap
# Prompts and evals
Prompt parts | Role, task, context, format, limits
Eval set | Typical, edge, risky cases
Scoring | Criteria, threshold, by category
Regression | Rerun on each prompt change, each model change
```

```flashcards
Eval set | A set of test questions with expected answers.
Threshold | The score needed to pass.
Regression | A fall in quality after a change.
Category view | Read results by group, not only the average.
```
