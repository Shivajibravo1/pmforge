## "We are inside the firewall, so we are safe"

A Nimbus contractor's laptop is infected with malware at home. On Monday, it connects to the corporate network. By Wednesday, the malware has reached a file server holding order exports, because once inside, everything trusted everything else.

```chat
# Incident review, Thursday, 10:00 AM
Elena Rossi | CISO | The laptop had a valid login and was on the internal network, so every system trusted it.
Network engineer | Infrastructure | Our design assumed that inside means safe.
Daniel Okafor | Sponsor | Is that still a reasonable assumption?
```

Traditional security treated the network like a castle: a strong wall, and trust inside. That model fails when users work from anywhere, applications live in the cloud and attackers, once in, move freely. Zero trust replaces location based trust with continuous verification. Never trust, always verify.

```key
Zero trust means every request is verified based on identity, device, context and policy, with the least access needed, and the assumption that a breach can happen.
```

## Core principles

```cards
key | Verify explicitly | Check identity, device health, location and risk on every access. | One login that grants wide access for hours.
lock | Least privilege | Give only the access needed, for only as long as needed. | Standing administrator rights.
alert | Assume breach | Design to limit damage and detect quickly. | Flat networks and shared accounts.
```

The principles are commonly attributed to frameworks such as NIST SP 800-207 on zero trust architecture. Check the current publication for the exact definitions.

```ref
NIST | SP 800-207 Zero Trust Architecture | Core idea: no implicit trust based on network location. Verify each request using identity, device and context.
CISA | Zero Trust Maturity Model | A staged path across identity, devices, networks, applications and data.
```


## What changes in practice

```cards
user | Strong identity | Multi factor authentication, single sign on, conditional access. | Weak methods, such as SMS only, for privileged users.
laptop | Device trust | Only managed, healthy devices reach sensitive systems. | Personal unmanaged devices with full access.
network | Segmentation | Small zones with controlled paths, not one flat network. | Lateral movement after one compromise.
eye | Monitoring | Log and analyse activity, and respond. | Logs that nobody reads.
database | Data protection | Classify, encrypt and control access to data. | Sensitive data copied into unmanaged places.
```

## A request in a zero trust model

```flow
Request | A user or service asks for access
Identify | Strong authentication of the user or workload
Assess | Device health, location, behaviour, risk
Decide | Policy grants minimal access, or denies, or asks for more proof
Monitor | Session is logged and re-evaluated continuously
```

## Your decision

Daniel asks for the quickest way to be "zero trust" by the end of the quarter.

```decision
? What do you tell him?
- Buy a zero trust product, and declare it done | No single product delivers zero trust, and the gaps remain.
- Say it takes years, and do nothing yet | You lose the chance to reduce the biggest risks now.
+ Present it as a journey, start with the highest value steps: multi factor authentication for everyone, privileged access control, conditional access for cloud services and segmentation of the most sensitive systems, and report progress against a maturity model | Visible risk reduction in a quarter, with a direction beyond.
= Zero trust is a strategy delivered in steps. Start where risk reduction per effort is highest.
```

## AI and zero trust

```cards
robot | AI agents are identities | An agent that calls tools needs its own identity and least privilege. | Agents running with a developer's full credentials.
database | Retrieval and permissions | The assistant must respect each user's access to documents. | An assistant that reveals documents the user cannot open.
network | Outbound control | Limit where AI services can send data. | Data sent to unapproved endpoints.
```

```ai
Shift | Zero trust applies to AI agents: each needs its own identity and narrow permissions.
Example (illustrative) | An agent has access to every mailbox. After review, it gets its own identity and per task permissions, and each tool call is logged.
Use AI to | Draft access policies and review permissions.
Keep human | Approving access. A person with authority grants each permission, reviews it regularly and removes it when no longer needed.
Risk | An agent running with broad credentials.
Control | Give every agent its own identity, grant per tool and per task permissions, enforce the user's access rights during retrieval and log every tool call.
Interview line | I apply zero trust to AI: an identity per agent, per tool permissions, the user's own access rights in retrieval and logging of every tool call.
```

```ref
OWASP | Top 10 for LLM Applications, excessive agency | An AI agent is a non human identity. Give it least privilege and log its actions.
```

```cards
cpu | AI engineer | Gives the model service only the access it needs. | Broad access for convenience.
shield | AI security consultant | Defines identity, device and data checks for AI tools. | Perimeter thinking.
wrench | Agent harness engineer | Enforces per request authorisation and logging. The term is not standardised, so confirm the scope. | Shared service keys.
users | Identity team | Owns identities, roles and conditional access. | Service identities unmanaged.
code | Traditional developers | Call AI services with scoped, short lived credentials. | Keys in code.
```

```incident
# Agent given broad access in the name of convenience (illustrative)
What happened | An AI agent was given one service account with wide read access to internal systems so it would work in testing.
Impact | A prompt injection in a document led the agent to read data the user was not entitled to see.
Root cause | The agent ran with its own broad rights and not the user's, and access was not checked per request.
Resolution | The team scoped access, passed user identity through, added per request checks and logged every tool call.
PM move | Apply least privilege and per request checks to AI agents.
```
