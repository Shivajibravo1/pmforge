## The date nobody can move

Daniel looks at your schedule. "The penetration test takes two weeks. Can we shorten something so we launch earlier? Which task can we squeeze?"

You have forty tasks on the plan. Squeezing the wrong one changes nothing. Squeezing the right one moves the date. The difference is the critical path.

```chat
# Planning session, Thursday, 10:30 AM
Daniel Okafor | Sponsor | Everyone says they are busy. Where do I put more people to finish sooner?
Rahul Mehta | Lead developer | If you add people to the interface work it will not finish faster. It is waiting on the vendor.
Elena Rossi | CISO | The pen test cannot start until the build is stable. That is fixed.
```

```key
The critical path is the longest chain of dependent tasks. It sets the earliest finish date. A delay on any task on it delays the project day for day.
```

## A small worked example

Illustrative network, durations in days. A comes first. B and C can run in parallel after A. D needs both B and C.

```flow
A, Design | 3 days
B, Build the portal | 5 days
C, Prepare test data | 2 days
D, Test and fix | 4 days
```

Two paths exist. Path A, B, D takes 3 + 5 + 4 = 12 days. Path A, C, D takes 3 + 2 + 4 = 9 days. The longest is 12, so A, B, D is critical and the project takes 12 days. Task C has float: it can slip by 12 minus 9 = 3 days without delaying the finish.

```stats
12 | Project duration (days)
9 | Length of the other path
3 | Float on test data (days)
```

## What to do with that

```cards
zap | Crash the critical path | Add resource to critical tasks that can be sped up, or overlap tasks that can run in parallel. | Adding people to a task that cannot be split makes it slower.
clock | Protect float | Float is a buffer, not free time. Use it deliberately. | The float is consumed silently and a second path becomes critical.
link | Dependencies | Finish to start is most common. Also start to start and finish to finish. | A hidden dependency, such as waiting on the vendor, makes the plan fiction.
```

## Your decision

Daniel wants the launch two weeks earlier. The pen test, which is on the critical path, takes two weeks.

```decision
? What do you recommend?
- Cut the pen test to one week to save time | You halve the security evidence. If something is found at go-live, you pay far more than the week you saved.
- Start the pen test now, before the build is stable | Findings against unfinished software are meaningless, and the test is wasted.
+ Show Daniel the critical path, then look for savings on it that do not lower quality, such as preparing the test environment earlier or doing the vendor interface in parallel, and say what each saving costs | He sees where time can really be found, and which options are real.
= Look for time on the critical path without reducing quality. Never trade away evidence for days.
```

## When the plan lies

```timeline
Week 1 | Plan shows go-live in week 14 | ok
Week 5 | Vendor interface not in the plan as a dependency | warn
Week 8 | Vendor slips two weeks, nobody expected it | bad
Week 10 | Critical path now runs through the vendor, date moves | bad
```

```ai
AI can draft a schedule from a WBS, which is useful for a first pass. Check every dependency yourself: the assistant does not know that your vendor needs three weeks to open a firewall port.
```

## Check your understanding

```quiz
? Path 1 takes 14 days and path 2 takes 10 days. Which is critical, and what is the float on the other?
- Path 2, with 4 days of float
+ Path 1, and path 2 has 4 days of float
- Both, with no float
= The longest path is critical. The shorter one has float equal to the difference, 14 minus 10 = 4 days.
```

## What to remember

```checklist
Critical path: the longest chain of dependent tasks
Float is the delay a task can take without moving the finish
Add resource only where the task can be sped up
Look for time on the critical path without cutting quality
Hidden dependencies, such as vendors, make plans lie
```
