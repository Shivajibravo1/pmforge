## Your job in one sentence

```key
An enterprise IT project manager turns a business need into a working, supported technology change, on an agreed date and budget, without breaking what already runs.
```

```flow
Business need | Someone needs an outcome
Plan | Scope, budget, date, risks
Build | Team delivers the change
Prove | Test, demo, security review
Run | Operations supports it live
```

## What changes when the project is IT

In a non-IT project the deliverable is usually visible. In IT it is mostly invisible: code, configuration, data, integrations, access rights. You cannot walk the site and see progress, so you manage through evidence: demos, test results, environment status and working software.

Three realities shape every IT project you will lead:

```cards
server | Production is shared | Your change lands in a live environment that other teams depend on. A good plan protects them.
link | Dependencies are hidden | An easy change often touches identity, network rules, a database, a vendor API and a security review.
eye | Quality is not obvious | A feature can look finished and still fail under load, expose data or be impossible to support.
```

## The people you work with

| Role | What they care about |
| --- | --- |
| Sponsor / business owner | Outcome, cost, date |
| CIO / IT head | Fit with architecture, run cost, risk |
| CISO / security | Data protection, compliance, vulnerabilities |
| Operations / support | Stability, monitoring, handover |
| Vendors | Scope clarity, change requests, payment |
| Delivery team | Clear priorities, fewer interruptions |

## What good looks like on Day 1

A strong IT PM can answer five questions without notes:

```checklist
What business problem are we solving?
What exactly is in and out of scope?
Who decides?
What can go wrong first?
How will we know it works?
```

```quiz
? A demo looks perfect, but nobody has said which environment it ran in. What should you ask first?
- Can we add more features before launch?
+ Is this running in a test copy or in production, and what is not tested yet?
- Who designed the screens?
= In IT you manage through evidence. The environment and the untested gaps tell you how much the demo proves.
```

## Check yourself

```tip
Pick a change currently happening in your organisation. Name the sponsor, the owner of the production system it touches, and the one dependency most likely to delay it. If you cannot name all three, that is your first piece of project work.
```
