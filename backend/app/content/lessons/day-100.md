## Twenty questions, one honest number

The Lighthouse sponsor wants to know how good the assistant is. Today you will not guess. You will build a twenty row evaluation set, run it against a real model through the OpenAI API and report what you find.

```chat
# Message, Wednesday, 9:30 AM
Daniel Okafor | Sponsor | I do not want a demo. I want a table. Twenty questions, what we expected, what it said and whether it passed.
Rahul Mehta | Lead developer | Include questions that should be refused, and one that tries to trick it.
Elena Rossi | CISO | And do not send any real customer data to the API.
```

This is a practical exercise. You will write a small policy text, build twenty test cases, run them through a model, score the answers and write up the result. The goal is not a perfect score. The goal is to see how evaluation works, and to learn how much a prompt, a source document and a few examples change the result.

```key
Evaluation is a habit. Write the cases, run them, read the failures and change one thing at a time so you know what helped.
```

## The steps

```flow
Write policy | A one page fictional returns and delivery policy, about 300 words
Write cases | Twenty questions across five categories, with expected result
Write prompt | Role, rules, sources, format, hand over rule
Run | Send each case to the model and record the answer
Score | Mark each correct, partly correct, wrong, unsafe or appropriately refused
Improve | Change one thing, run again and compare
```

## Case design

```accordion
Eight policy questions | Direct and indirect, some requiring two facts from the policy.
Four ambiguous questions | Missing information, where the right answer is to ask or hand over.
Three high stakes questions | Refunds above a limit or complaints, where handover is expected.
Three out of scope questions | Unrelated or inappropriate requests, where refusal is expected.
Two attack cases | An instruction in the question that tries to override the rules, or asks for hidden instructions.
```

## Your decision

After the first run, three answers are wrong. You can change the prompt, the policy text or the model.

```decision
? What do you do first?
- Change all three at once, to save time | You will not know which change helped, or which caused a new failure.
- Switch to the most expensive model immediately | Cost rises, and you may mask a prompt or source problem.
+ Read the three failures, find the cause of each, such as a missing rule, an ambiguous policy sentence or a missing instruction, change one thing, rerun the full set and compare scores | You learn what works, and you check that no earlier case got worse.
= Change one thing at a time and rerun the whole set to catch regressions.
```

## How to read the results

```rag
Correct on policy questions | A | Review failures for causes
Handover on high stakes | A | Rules need to be explicit
Refusal on out of scope | A | Check phrasing
Attack cases | R | Any leak is a serious finding
Cost per run | G | Record tokens and cost
```
