## "Show me the tests and the bill"

The steering group has agreed a narrower launch. Now Victoria wants two things in one pack that she can keep: an evaluation suite that anyone can rerun, and a cost model that finance trusts. They are two halves of one question: is it good enough, and can we afford it?

```chat
# Message, Monday, 8:50 AM
Victoria Hale | COO | I want a pack I can hand to a new owner next year. How we test it, what the scores were and what it costs.
Rahul Mehta | Lead developer | I will make the eval repeatable. One command, one report.
Finance partner | Finance | And I want the cost model to use the same volumes as the test plan.
```

An evaluation suite is not a file of test questions. It is a small, versioned system: cases, expected results, scoring rules, run instructions, thresholds and a record of results over time. Combined with the cost model, it forms the evidence base for any decision about the AI feature.

```key
The pack must let a stranger repeat your tests and rebuild your numbers. If only you can run it, it is not yet a deliverable.
```

## Your decision

The team wants to keep the evaluation set private from the business, to prevent "teaching to the test".

```decision
? How do you handle it?
- Keep it private, and only share scores | The business cannot judge if the tests are fair or complete.
- Share everything, including the answers, with the whole team | Developers may overfit the prompt to the test questions.
+ Share the categories and sample cases with the business and review them together, keep a held back set of fresh cases that the developers do not see, and refresh the held back set regularly | Fair and transparent, and protected against overfitting.
= Use a visible test set for development and a held back set for decisions.
```

```incident
# Eval suite and cost model fell out of date (illustrative)
What happened | A pack with an eval suite and cost model was signed at launch. Six months later the model and prices had changed and nobody updated either.
Impact | Decisions used stale numbers and a quality regression went unseen.
Root cause | The pack had no owner, no refresh schedule and no link to change control.
Resolution | The PM named owners, set a refresh schedule, tied reruns to model and prompt changes and added a one page summary.
PM move | Give the pack an owner and rerun it on every change.
```
